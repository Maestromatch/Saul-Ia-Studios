# Manual del creador — Saul IA Studios v1

> Creador y operador inicial: **Saul**.  
> Objetivo: ejecutar servicios de la agencia con orden, velocidad y menos errores.

## Principio maestro

No empieces a construir si no estan claros:

1. Dolor del cliente.
2. Resultado prometido.
3. Entregables.
4. Datos necesarios.
5. Fecha de entrega.
6. Forma de pago.
7. Criterio de "terminado".

Si falta uno, estas entrando a estancarte.

---

# Flujo general para cualquier servicio

## Paso 1 — Calificar al cliente

Preguntar:
- ¿Que vendes?
- ¿A quien le vendes?
- ¿Por donde te llegan clientes?
- ¿Que problema quieres resolver primero?
- ¿Tienes fotos, servicios, precios o preguntas frecuentes?
- ¿Quien respondera los leads?
- ¿Tienes presupuesto para implementar?

Decision:
- Si no tiene oferta clara, vender mini-servicio o diagnostico.
- Si tiene oferta clara y dolor fuerte, vender Pack IA/Growth.

## Paso 2 — Elegir servicio correcto

No vender todo.

Usar esta regla:

- Desorden WhatsApp -> Auditoria WhatsApp / Bot IA.
- No tiene presencia -> Mini Landing / Pack IA.
- No recibe clientes -> Ads Growth.
- Tiene fotos pero no publica -> Content Engine.
- Publica manual y pierde tiempo -> Publicador Tanque.
- No mide leads -> CRM/Dashboard.
- No tiene empresa -> Formaliza.

## Paso 3 — Cobrar antes de trabajar

Reglas:
- Mini-servicios: 100% adelantado.
- Servicios $150K+: 50% anticipo, 50% entrega.
- Mensualidades: pago antes del mes.

No iniciar sin pago o acuerdo escrito.

## Paso 4 — Onboarding

Pedir solo lo necesario para ese servicio.

No abrir 20 preguntas si el servicio es chico.

Datos base:
- Nombre negocio.
- Responsable.
- WhatsApp.
- Rubro.
- Servicios.
- Zona.
- Fotos/logos si aplica.
- Links actuales.

## Paso 5 — Crear carpeta del cliente

Ruta:

`clientes/NOMBRE-CLIENTE/`

Estructura minima:

```text
/01-onboarding
/02-construccion
/03-entrega
/04-testimonio
/05-growth
README.md
```

## Paso 6 — Ejecutar con checklist

Cada servicio debe tener:
- checklist inicio.
- checklist QA.
- checklist entrega.

Si no hay checklist, se improvisa y aparecen errores.

## Paso 7 — Entregar con resumen

Toda entrega debe incluir:
- Que se hizo.
- Como usarlo.
- Que no incluye.
- Proximo paso recomendado.
- Oferta de upgrade.

## Paso 8 — Pedir testimonio

Despues de entregar:

> ¿Me puedes dejar un testimonio corto sobre que problema te ayudo a ordenar y como fue trabajar conmigo?

## Paso 9 — Documentar aprendizaje

Cada servicio debe dejar:
- 1 mejora al proceso.
- 1 objecion nueva.
- 1 plantilla reutilizable.
- 1 error evitado para la proxima.

# Anti-estancamiento

## Si te quedas pegado por falta de datos

Hacer:
- enviar lista exacta de datos faltantes.
- poner fecha limite.
- ofrecer trabajar con supuestos marcados.

No hacer:
- esperar indefinidamente.
- inventar datos criticos.
- construir sin alcance.

## Si el cliente no responde

Secuencia:
1. Recordatorio 24h.
2. Recordatorio 72h.
3. Pausar proyecto.
4. Reactivar cuando entregue datos.

## Si el cliente cambia alcance

Responder:

> Eso no estaba incluido en el alcance inicial. Lo podemos agregar como extra o dejarlo para una fase 2.

## Si algo falla tecnicamente

Orden:
1. Reproducir error.
2. Captura/log.
3. Identificar si es credencial, API, dato o codigo.
4. Arreglar una cosa a la vez.
5. Documentar en learning log.
